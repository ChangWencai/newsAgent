# 功能景观：AI 新闻自动化流水线

**领域：** AI 驱动的内容自动化生产与发布
**研究日期：** 2026/05/09

## 功能分级总览

```
差异层 (Differentiators)              ── 竞争优势
  ├── 智能风格-话题匹配
  ├── 多角度文章生成（去重+角度区分）
  ├── 发布时间优化
  └── 数据驱动的内容策略

必备层 (Table Stakes)                  ── 缺失 = 产品不完整
  ├── 多平台热点聚合
  ├── 内容去重
  ├── 合规检查（敏感词/违规内容过滤）
  ├── 反检测发布（浏览器指纹伪装）
  └── 基础数据分析（阅读量/收益追踪）

反功能层 (Anti-Features)               ── 刻意不构建
  ├── 自动生成评论/互动
  ├── 全自动无人工审核
  ├── 多平台同时发布
  └── 视频/图片自动生成
```

## 必备功能 (Table Stakes)

缺少任何一个都会让系统感觉不完整或不可用。

### 1. 多平台热点聚合

**为什么必备：** 单一平台（抖音）热点覆盖范围有限。同一条新闻在不同平台的热度、讨论角度、用户画像完全不同。只有多平台聚合才能确保全面覆盖热点。

**具体实现要素：**

| 数据源 | 覆盖领域 | 现有方案 | 复杂度 |
|--------|----------|----------|--------|
| 微博热搜 | 社会新闻、娱乐、突发 | DailyHotApi `/weibo` | 低 |
| 知乎热榜 | 深度讨论、专业观点 | DailyHotApi `/zhihu` | 低 |
| 百度热搜 | 全面综合、搜索热度 | DailyHotApi `/baidu` | 低 |
| B站热门 | 年轻受众、亚文化 | DailyHotApi `/bilibili` | 低 |
| 抖音热搜 | 短视频热点、娱乐 | 已有实现 | 已完成 |
| 36氪热榜 | 科技、创业、商业 | DailyHotApi `/36kr` | 低 |
| 头条热榜 | 综合新闻、下沉市场 | DailyHotApi `/toutiao` | 低 |
| 澎湃热榜 | 严肃新闻、时政 | DailyHotApi `/thepaper` | 低 |

**推荐方案：** 使用 [DailyHotApi](https://github.com/imsyy/DailyHotApi)（支持 40+ 平台），自建服务或调用已部署实例。避免逐个平台编写爬虫。当前系统已经使用的今日热榜 API 与 DailyHotApi 类似，可评估切换或并行使用。

### 2. 内容去重

**为什么必备：** 多平台热点必然导致大量重复话题（同一条新闻在微博、知乎、百度同时上热搜）。没有去重会造成：
- 同一话题生成多篇相似文章
- 头条平台判定重复内容，降低推荐权重
- 浪费 AI 生成配额和 API 调用费用

**具体实现要素：**

| 去重层级 | 方法 | 说明 |
|----------|------|------|
| 标题精确去重 | 标题完全匹配 | 当前已有 `topic_exists(title)` |
| 标题模糊去重 | 编辑距离 < 阈值 | 同一话题不同表述 |
| 语义去重 | Embedding 余弦相似度 | 同一事件不同描述 |
| 内容去重 | SimHash / MinHash | 已生成文章的近似重复检测 |

**当前状态：** 系统仅有精确标题匹配（`db.topic_exists()`），无法处理同义标题或同一事件不同表述。这是必须升级的基础能力。

**关键算法：**
- **编辑距离（Levenshtein）：** 适用于标题级去重，计算两个字符串的最小编辑操作数。阈值建议设为标题长度的 20%。
- **SimHash：** 适用于大规模文档级近似重复检测。Google 爬虫使用的核心算法。将文档转为指纹后通过汉明距离比较。
- **Embedding 余弦相似度：** 最准确但成本最高。需要调用 Embedding API 将标题转为向量，再计算相似度。适合中等规模（<10万条）。

### 3. 内容合规检查

**为什么必备：** 中国互联网内容监管严格。AI 生成内容若包含敏感信息会导致：
- 头条号封号/降权
- 法律风险
- 品牌声誉损失

**具体实现要素：**

| 检查类型 | 实现方式 | 触发时机 |
|----------|----------|----------|
| 敏感词过滤 | 关键词匹配 + 敏感词库 | 生成后、发布前 |
| 政治敏感检测 | LLM 二次审核 prompt | 生成后 |
| 虚假信息风险 | 关键事实交叉验证 | 生成后 |
| AI 内容标识 | 根据平台要求添加声明 | 发布时 |
| 版权风险 | N-gram 相似度检测 | 生成后 |

**关键数据：** 2023 年《互联网信息服务深度合成管理规定》要求 AI 生成内容必须标识。头条号平台也有相关规定。

### 4. 反检测发布（浏览器指纹伪装）

**为什么必备：** 当前系统使用 Playwright 进行浏览器自动化发布。头条等平台有反爬虫/反自动化检测系统，检测手段包括：
- `navigator.webdriver` 属性检测
- Canvas / WebGL 指纹检测
- 浏览器插件列表检测
- 行为分析（鼠标轨迹、输入速度）

**具体实现要素：**

| 检测手段 | 绕过方法 | 当前状态 |
|----------|----------|----------|
| `navigator.webdriver = true` | JS 注入覆盖为 `false` | 未实现 |
| Canvas 指纹 | 添加微小噪声 | 未实现 |
| WebGL 指纹 | 覆盖渲染器信息 | 未实现 |
| 浏览器插件检测 | 伪造合理插件列表 | 未实现 |
| 自动化标志 | 隐藏自动化控制痕迹 | 未实现 |
| Cookie/Session 检测 | 使用真实登录 Cookie | 已实现 |

**推荐方案：** 使用 `playwright-stealth` 库（[PyPI](https://pypi.org/project/playwright-stealth/)），它是 `puppeteer-extra-plugin-stealth` 的 Playwright 移植版。但需注意作者警告：该库仅能绕过最简单的检测，对于头条这类有专业反爬系统的平台，效果可能有限。更可靠的方案是在 `_create_context()` 中注入 stealth 脚本并配合真实浏览器 User-Agent 和合理的行为模拟。

### 5. 基础数据分析

**为什么必备：** 没有数据反馈就无法优化内容策略。不知道哪些话题带来流量、哪些风格更受欢迎、什么时间发布效果最好，系统只能盲打。

**具体实现要素：**

| 数据指标 | 采集方式 | 用途 |
|----------|----------|------|
| 文章阅读量 | 头条号后台抓取 | 衡量内容受欢迎度 |
| 文章收益 | 头条号后台抓取 | 衡量变现效率 |
| 发布时间 vs 阅读量 | 内部记录 + 后台数据 | 优化发布时机 |
| 话题类别 vs 阅读量 | 内部分类 + 后台数据 | 优化选题策略 |
| 风格 vs 阅读量 | 内部记录 + 后台数据 | 优化风格匹配 |

## 差异化功能 (Differentiators)

这些功能能让系统从"能用"变成"好用"，形成竞争优势。

### 1. 智能风格-话题匹配

**价值主张：** 当前系统的 `detect_style()` 基于关键词匹配，仅支持 3 种风格且匹配逻辑简单。智能匹配能显著提升文章质量和阅读量。

**具体实现方向：**

| 匹配维度 | 说明 | 示例 |
|----------|------|------|
| 话题性质分析 | 用 LLM 判断话题类型（严肃/轻松/争议） | "某明星塌房" -> 娱乐解读，"两会政策" -> 新闻报道 |
| 受众画像匹配 | 不同平台热点的受众不同 | B站热点 -> 轻松风格，知乎热点 -> 深度分析 |
| 时效性判断 | 突发 vs 持续话题 | 突发新闻 -> 新闻报道，长期话题 -> 深度分析 |
| 情感倾向分析 | 负面/正面/中性 | 负面事件 -> 客观报道，正面事件 -> 轻松解读 |

**实现方案：**
- 在 `generate_article()` 之前增加一个轻量级 LLM 调用，让模型分析话题并返回推荐风格
- 使用 system prompt 指定分析维度，返回 JSON 格式的风格推荐结果
- 成本：额外增加一次 API 调用（约 200 tokens），可忽略不计

### 2. 多角度文章生成（去重 + 角度区分）

**价值主张：** 同一个热点话题可能在多个平台上热搜。与其跳过重复话题，不如从不同角度生成多篇文章，最大化利用热点流量。

**具体实现方向：**

| 角度策略 | 说明 | 示例 |
|----------|------|------|
| 事实报道角度 | 仅陈述事实，客观中立 | "XX 事件始末" |
| 深度分析角度 | 分析原因、影响、背景 | "XX 为何会发生？三大原因解析" |
| 观点评论角度 | 表达立场、引发讨论 | "XX 事件：我们该反思什么？" |
| 趣味解读角度 | 轻松幽默，降低门槛 | "XX 事件的 N 个细节，最后一个绝了" |
| 相关延伸角度 | 连接其他话题，扩大受众 | "从 XX 看 YY 行业的未来" |

**去重 + 区分的完整流程：**
1. 收到新热点 -> 检查是否已有相同/相似话题
2. 如果已有 -> 检查已有文章的角度
3. 选择一个未使用过的角度生成新文章
4. 如果所有角度都已覆盖 -> 跳过该话题

**数据模型变更：** `hot_topics` 表需要增加 `angle` 字段，或新建 `topic_angles` 表记录已使用角度。

### 3. 发布时间优化

**价值主张：** 发布时间对阅读量有显著影响。在用户活跃高峰期发布可以获得更多的初始推荐和互动，从而触发平台算法的更大推荐量。

**关键时段（头条号平台）：**

| 时段 | 活跃度 | 适合内容 |
|------|--------|----------|
| 07:00-09:00 | 高 | 新闻资讯、早报 |
| 11:30-13:30 | 高 | 轻松娱乐、午间阅读 |
| 17:30-19:00 | 中高 | 下班通勤内容 |
| 20:00-22:00 | 最高 | 深度分析、热点评论 |
| 22:00-24:00 | 中 | 娱乐八卦、情感内容 |

**实现方案：**
- 在 APScheduler 调度中增加"智能发布"模式
- 根据文章风格/话题类别自动选择最佳发布时段
- 文章生成后不立即发布，而是排队等待最佳时段
- 新闻报道 -> 早上 7-9 点；娱乐解读 -> 晚上 8-10 点

### 4. 数据驱动的内容策略

**价值主张：** 通过分析历史数据，自动调整内容策略，实现"越用越聪明"。

**具体实现：**

| 策略维度 | 数据来源 | 自动调整 |
|----------|----------|----------|
| 平台热度 | 多平台数据采集频率 | 热度高的平台增加抓取权重 |
| 话题偏好 | 文章阅读量统计 | 高阅读量话题类别优先选题 |
| 风格效果 | 风格 x 阅读量关联 | 高效风格提高使用频率 |
| 发布时机 | 发布时间 x 阅读量关联 | 自动调整发布时段 |

**实现方案：**
- 新增 `analytics` 模块，定期（每日）从头条号后台采集已发布文章数据
- 将采集数据写入 SQLite `article_analytics` 表
- 在选题和风格匹配决策中参考历史表现数据
- Web UI 新增"数据分析"页面展示趋势图表

## 反功能 (Anti-Features)

明确不构建这些功能，避免浪费资源。

### 1. 自动生成评论/互动

**为什么不构建：**
- 违反平台规则，高风险封号
- 自动生成的评论质量差，容易被识别
- 投入产出比极低（需要大量账号资源）
- 法律风险（虚假互动）

**应该做：** 专注于内容生产质量，让真实用户产生互动。

### 2. 全自动无人工审核

**为什么不构建：**
- 当前 PROJECT.md 中"全自动无人工审核"的决策需要重新审视
- AI 生成内容可能出现事实错误、敏感内容、格式问题
- 发布后发现问题的修改成本远高于发布前审核
- 但完全人工审核又违背自动化目标

**应该做：** 实现"半自动"模式——自动审核规则（敏感词、格式、合规检查）通过后自动发布，高风险内容进入人工审核队列。审核队列在 Web UI 中展示，支持一键批准/拒绝。

### 3. 多平台同时发布（头条以外）

**为什么不构建：**
- 每个平台的发布流程、内容格式、规则完全不同
- 维护多个平台的 Playwright 自动化成本极高
- 头条号的流量变现效率最高（千次阅读收益高于其他平台）
- 微信公众号需要企业认证，个人号限制多
- 微博对 AI 内容的推荐权重低

**应该做：** 深耕头条号一个平台，把内容质量和发布效率做到极致。如果未来要扩展平台，优先考虑百家号（同属字节生态，规则相似）。

### 4. 视频/图片自动生成

**为什么不构建：**
- 视频生成成本极高（AI 视频生成工具费用 + 渲染时间）
- 图片生成版权风险大（AI 生成图片的版权归属仍有争议）
- 纯文本内容在头条号上已经能获得大量流量
- 技术复杂度跨度过大（需要完全不同的技术栈）

**应该做：** 在文章中使用简单的文字排版和结构化格式（列表、加粗、引用），提升阅读体验。

## 功能依赖关系

```
多平台热点聚合
  └──> 内容去重（需要跨平台去重能力）
         └──> 多角度文章生成（需要知道已有角度）
                └──> 智能风格-话题匹配（需要角度信息来选择风格）
                       └──> 合规检查（需要检查生成的内容）
                              └──> 反检测发布（需要安全地发布到平台）
                                     └──> 基础数据分析（需要已发布文章的数据）
                                            └──> 数据驱动的内容策略（需要足够数据积累）
```

## MVP 推荐

按优先级排序：

### 第一优先级（核心扩展）
1. **多平台热点聚合** -- 将 DailyHotApi 作为新 Crawler 实现，支持微博/知乎/百度三个核心平台
2. **内容去重（语义级）** -- 用编辑距离 + Embedding 相似度替代当前的精确匹配
3. **合规检查** -- 敏感词过滤 + AI 审核 prompt

### 第二优先级（效率提升）
4. **反检测发布** -- 集成 playwright-stealth + 行为模拟
5. **智能风格匹配** -- LLM 分析话题并推荐风格
6. **多角度文章生成** -- 角度记录 + 角度选择策略

### 第三优先级（长期优化）
7. **基础数据分析** -- 头条号后台数据采集
8. **发布时间优化** -- 基于数据的发布时段调度
9. **数据驱动策略** -- 自动化策略调整

### 延后
- 视频/图片生成：技术跨度太大，延后
- 多平台发布：延后，先做好头条
